## Q2 止损规则：只上移不下移是有意设计吗？——【阻塞】

### 代码事实

当前实现是**「只上移不下移」的移动止损**，共三条调用路径：

| 时机 | 调用链 | 计算方式 |
| --- | --- | --- |
| 首次设置 | `ui/main_window.py:544` → `alert_engine.py:83` | `max(lows[买入日:])`，即买入日至今所有日线 low 的最大值（`alert_engine.py:139-142`） |
| 盘中每轮刷新 | 同上 | `max(当前止损, 今日最低)`（`alert_engine.py:159`） |
| 每日 15:05 后 | `ui/main_window.py:501` → `alert_engine.py:315` | `max(前一止损, 今日最低)`（`core/technical.py:395-407`） |

三条路径在数学上是自洽的：首次「追赶」到移动止损应有的位置，之后逐日抬升，与「从买入日逐日执行 `max(昨日止损, 今日最低价)`」等价。

**取数窗口为最近 120 个交易日**（`alert_engine.py:120`、`:327`）。

当前效果：价格上涨时止损线会贴着历史最高 low 上移，因此**任何正常回撤都可能触发止损**。这在趋势行情里是保护，在震荡行情里可能导致频繁被自己的波动打出。

### 需要确认

- [ ] **(a) 「只上移不下移」是有意设计**，保持现状。
- [ ] **(b) 需要回撤容忍**（例如「从持仓期最高价回撤 N%」），N = ____ 。
- [ ] **(c) 应该改用其他规则**：「N 日最低价」/ 「ATR 倍数」/ 「固定百分比」，请说明：________________
- [ ] **(d) 首次设置不应该「追赶」**，应按别的方式取初始值：________________

**另需确认取数窗口：**

- [ ] 120 个交易日足够，长线持仓不必覆盖更早的极值。
- [ ] 窗口应放宽到 ____ 天，或改为按首次买入日动态取数。

> 现状说明：若持仓超过 120 个交易日，初始止损只覆盖窗口内的极值，会**低于**应有值（比预期更宽松）。目前已加 warning 日志提示人工复核，但**没有自动放宽窗口**，等这条确认后再动。

## Q3 做 T 的资金与仓位记账口径——【阻塞】

### 代码事实

`core/trading/t_trader.py` 文件头声明的规则是：

```
底仓 = N * 10000 元 (以股数表示)
可用资金 = N * 10000 元
每日最多做T N 次，每次固定 10000 元
```

四条记账分支的方向互不一致：

| 路径 | `open()` | `check_close()` | 单轮净效果 |
| --- | --- | --- | --- |
| 先买后卖 | 资金 −10000（`:156`） | 底仓 **+qty**（`:219`） | 资金 −10000，底仓 **+qty** |
| 先卖后补 | 底仓 −qty（`:162`） | 资金 **+10000**（`:224`） | 资金 **+10000**，底仓 −qty |

即：**「卖出所得」在两条路径上都没有被正确记入**——先买后卖的平仓不回补资金，先卖后补的开仓不记录卖出所得（反而在回补时才加资金）。

隔离环境实测（`n_lots=5`，初始资金 50000 / 底仓 5000 股，10.00 开、10.10 平）：

```
先买后卖 单轮：   资金 50000 -> 40000    底仓 5000 -> 6000
先买后卖 连做3轮：资金 50000 -> 20000    底仓 5000 -> 8000
先卖后补 单轮：   资金 50000 -> 60000    底仓 5000 -> 4000
```

**级联后果**：先买后卖每轮净减 10000，而每日上限 `max_trades = n_lots = 5`——**第 5 轮资金归零后 `open()` 在 `:154` 静默返回 `None`**，当天剩余时段做 T 全部失效，不报错、不记日志。

> 补充说明：`TTrader` 目前在 `ui/` 层**零引用**，仅 `core/trading/simulator.py` 与测试使用，所以当前不影响真实交易。但它会直接影响 `TTSimulator` 的仿真结论，且接线做 T 界面时必须先修。

## Q4 买点扫描的底分型确认，取值是否有意后移一根？——【阻塞】

### 代码事实

`detect_bottom_fractal()` 返回的是**分型最低价实际所在的原始 K 线索引**，即中间那根。

- docstring：`core/technical.py:155-156` —— 「若中间K线由包含合并产生，取分型最低价实际所在的原始K线」
- 旁证：`core/technical.py:183` 的 `get_latest_top_fractal` 直接用 `highs[idx]` 取顶分型价——说明「idx = 分型本身」是本项目的既有约定

而买点扫描里取的是：

```python
# core/buy_point_scanner.py:111-114
bottom_low    = w_arr["lows"][idx + 1]     # 右侧 K 线的最低价
confirm_close = w_arr["closes"][idx + 2]   # 再下一根的收盘价
```

上方注释写的是「确认: **第三K线收盘 > 底分型最低价**」。按 `idx` = 中间 K 线的语义，注释对应的写法应是 `lows[idx]` 与 `closes[idx+1]`。**代码与其自身注释整体后移了一根**，实际校验的是「第四根收盘 > 第三根最低」。
