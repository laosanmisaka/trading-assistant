# 使用手册

安装和首次启动见 [README](../README.md)。请使用专用 conda 环境 `trading-assistant-py312`。本工具维护用户手工记录，不自动下单。

## GUI 操作

- 预设分组为「持仓中」「已清仓」「跟踪中」，可另建自定义分组。
- 输入股票代码或名称搜索，添加到当前分组；名称库未命中时后台同步。连续添加的历史取数按队列执行。
- 双击股票切换 K 线/分时图。后台补齐历史后刷新图表，计算期间可继续操作。
- 右键股票可管理交易记录、手动提醒、交易纪律和缠论标注。
- 窗口关闭按钮最小化到托盘。菜单或托盘「退出」停止定时器并等待后台线程结束，再关闭应用；网络请求尚未返回时可能需要等待。

## 成交与持仓

成交按 `trade_date, id` 排序。新增、更改、删除历史成交会重新计算持仓：买入增加成本，卖出按当时移动平均成本减少剩余成本，清仓归零，下次买入开始新持仓周期。

- 表格浮动盈亏 = 当前持仓市值 − 剩余持仓成本。
- 交易对话框累计总盈亏 = 累计卖出金额 − 累计买入金额 + 当前持仓市值。
- 对话框百分比以累计买入金额为分母；它不是年化收益或组合回报。
- 无有效行情时不把价格当成零计算亏损。遗留超卖记录被标为无效，先核对成交；不会据此触发持仓提醒。
- 交易记录的金额没有自动加入真实券商费用；通用回测执行器另有费用模型。

## 提醒

手动止损与止盈独立保存；修改其中一项不会重置另一项，重启后恢复。清仓再买会清除上一持仓周期的自动提醒状态；明确保存的手动设置仍保留，请按需取消。

自动止损使用日线最低价只上移，当前历史扫描仍有 120 根窗口限制。自动止盈初值为当前持仓成本的固定倍率 `TAKE_PROFIT_LIMITUP_RATIO`，不是交易所涨停价；随后可锁定买入日之后的 **60min** 顶分型。成交记录只精确到日期，因此不采用买入当天的顶分型，避免把买入前结构当作买入后结构。详见 [业务口径](BUSINESS_RULES_CONFIRMATION.md)。

表格止损/止盈价格列和图表提醒线的历史占位尚未接通；提醒逻辑与这些显示项是不同边界，见 [已知限制](KNOWN_ISSUES.md)。

## 策略买点与图表

「三买监控」「策略买点」由脚本自动接管，请把手工关注股票放入其他分组。买点时间来自监控日志的 `conf`，显示近两个交易所开市日的最新有效首次入场。被撤销的几何不继续显示为有效买点；日志中的原始观察成交仍保留。

GUI 的三买标注使用本地日线/5min 缓存的可观察事件回放。缺少缓存不会伪造信号。新浪实时与 baostock 缓存起点、复权及修订不同，共享算法并不保证不同数据源信号完全相同。几何点仅是结构标记，不等于成交时刻。

`visualize_chan.py` 的旧多周期页面用于历史几何诊断，页面已标明其未来信息风险；不把该页面的旧多周期交易标记当作当前策略。GUI 不再展示旧多周期交易，仍保留几何结构标注。

## 数据与排障

`trading_assistant.db` 保存成交、分组和设置，修改前应备份；行情表是可重建缓存。启动先显示数据库快照，再排队拉取可用历史；跨日补齐日线并重建周/月线，60min 定期刷新。首次补齐可能比以前慢，源失败会记日志并重试。

- 搜索失败：查看 `logs/`，区分名称库同步失败与无匹配结果。
- 图表为空：检查后台取数状态、数据源连通和 `outputs/cache_min` 覆盖范围。
- 监控不运行：检查交易日历版本、watchlist schema 和错误退出状态，按 [运行手册](OPERATIONS.md) 重扫。
- 日历超出依赖的支持年份：更新 `exchange_calendars` 并跑测试；程序不会把工作日近似成交易日。

不要把本地套件通过解释为真实行情可靠、策略有效或 Windows 桌面已验收。验证边界见 [VALIDATION](VALIDATION.md)。
