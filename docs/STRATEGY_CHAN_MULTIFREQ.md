# 缠论多周期共振策略 —— 定义、实现与实测

**日期**：2026-09-17
**状态**：**已实现**（口径已确认，代码 + 43 条测试落地）
**代码**：`core/chan_strategy.py`｜**测试**：`tests/test_chan_strategy.py`

## 1. 结论先行

策略已按老三确认的口径实现并跑通完整闭环。

**但有两点必须先说清楚：**

1. **频率极低** —— 三重 AND 叠加后，在合成数据上实测约 **0.6~1 次买点/年**。
   真实行情会多一些，但这个量级意味着**单只股票一年可能一次信号都没有**。
   要形成可交易的信号流，需要**池化选股**（几百只里挑出当天触发的）。
2. **必须用真实数据复核** —— 项目数据库当前 `klines` / `klines_minute` 均为空，
   本文所有频率数字都来自**随机游走合成数据**，只能作量级参考。

## 2. 策略定义（老三 2026-09-17 确认）

### 2.1 买点：三重条件，有顺序、有时间窗

| 序 | 条件 | 时间窗 |
| --- | --- | --- |
| 1 | 日线出现**一买** | — |
| 2 | 出现**日线二买** | 一买之后 **15 个交易日**内 |
| 3 | 出现 **30 分钟二买** | 日线二买之后 **2 个交易日**内 |

三条依次满足的那一刻（30 分钟 bar 收盘）即为买点。

窗口按**交易日**计算（不是自然日），边界含端点：第 15 个交易日算在窗内，第 16 个不算。

### 2.2 卖点：日线均线的移动止损

> "均线最好是智能选取一直沿着上涨没有跌破的 5 或 10 日均线，可以先定为日线 MA5"

实现的解读（**待老三确认**）：

- 买入后以 **MA5** 为止损线
- 收盘跌破 MA5、但 MA10 仍完好 → **改用 MA10** 继续持有
- MA5、MA10 **双双被跌破** → 卖出

即"选出那条至今没被跌破的均线"，而不是"破 MA5 立刻清仓"。

### 2.3 成交时点：等确认，不抢跑

老三明确"不需要当时就知道，可以有半天到一天的延迟"。落地为：

| 动作 | 确认时点 | 成交时点 |
| --- | --- | --- |
| 买入 | 30 分钟二买 bar 收盘 | **下一根** 30 分钟 bar 收盘价 |
| 卖出 | 日线收盘跌破均线 | **次一交易日**收盘价 |

参数：`entry_delay_bars=1`、`exit_delay_days=1`。
这样回测与实盘看到的是同一时点的信息。

## 3. 实测结论（两条，都有数据支撑）

### 3.1 信号是「持续状态」，不是「点事件」

czsc 的信号列**不是 0/1**，而是持续状态字符串：

| 列名 | 取值 |
| --- | --- |
| `日线_D1B_BUY1` | `一买_19笔_任意_0` / `其他_任意_任意_0` |
| `日线_D1#SMA#21_BS2辅助V230320` | `二买_任意_任意_0` / `二卖_任意_任意_0` / `其他_任意_任意_0` |
| `30分钟_D1#SMA#21_BS2辅助V230320` | 同上 |

实测日线二买状态连续覆盖 **352 根 30 分钟 bar（约 44 个交易日）**。

→ 所以"出现二买"必须定义为**状态跃迁**（首次进入该状态的那一根）。
若按"值里含二买"判定，15 日窗口形同虚设（状态一开就是 44 天）。

### 3.2 日线信号在日内会翻转 → 取当日首根 bar 的值

实测 **418 个交易日中有 45 天**，日线二买在**同一交易日内发生翻转**
（早盘读到"其他"、尾盘变"二买"，或反之）：

```
2023-05-26: 首根=其他  末根=二买   日内取值数=2
2023-05-24: 首根=二买  末根=其他   日内取值数=2
2024-03-14: 首根=其他  末根=二买   日内取值数=2
```

原因是当天的日线 bar 尚未走完，czsc 会拿当天已发生的部分 30 分钟合成日线参与计算。

**本模块的处理**：日线信号按交易日取**首根 bar 的值**，等价于「上一交易日收盘确认」
的状态。好处是实盘开盘就能读到、回测与实盘一致；代价是日线信号滞后 1 个交易日。

> **对窗口的影响：无。**
> 一买、二买都整体后移 1 个交易日，位置差不变，`gap` 值与用真实发生日计算完全相同。

### 3.3 关于"未来函数"的结论修正

本文件 v1 曾判断"批量接口把日线信号回填到了当天第一根 30 分钟 bar 上，构成未来函数"。
**该判断不准确，此处更正：**

- 实测日线信号的日内变更发生在第 **1~7** 根 bar，**从不在第 0 根**（首根）
  —— 说明不是"回填到第一根"
- 切片重算（只喂到时刻 t）与全量回看的结果 **5/5 完全一致**
  —— 说明批量路径与因果路径等价，没有使用 t 之后的数据

**真正的问题是信号日内不稳定，不是未来函数。** 而"取当日首根 bar 值"这一处理，
同时消除了两者风险。

## 4. 实现

### 4.1 模块接口

```python
from core.chan_strategy import scan

result = scan(klines_30min, code="600000")   # klines: list[KLineData]
result.summary()
# {'买点数': 1, '已平仓': 1, '未平仓': 0, '胜率%': 0.0,
#  '平均收益%': -2.81, '平均持有交易日': 2.0, ...}

for t in result.trades:
    t.buy.dt, t.buy.price, t.buy.signal_dt     # 成交时刻 / 价 / 信号确认时刻
    t.buy.d1, t.buy.d2, t.buy.gap_1to2, t.buy.gap_2tom
    t.sell.dt, t.sell.price, t.sell.ma, t.sell.hold_days, t.sell.confirm_dt
```

### 4.2 关键参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `max_gap_1to2` | 15 | 一买 → 二买 的最大间隔（交易日） |
| `max_gap_2tom` | 2 | 日线二买 → 30 分钟二买 的最大间隔（交易日） |
| `ma_short` / `ma_long` | 5 / 10 | 卖出用的短/长均线 |
| `entry_delay_bars` | 1 | 买入成交相对信号 bar 的延迟（根） |
| `exit_delay_days` | 1 | 卖出成交相对确认日的延迟（交易日） |
| `ma_type` / `timeperiod` | SMA / 21 | czsc `cxt_second_bs` 的信号参数 |

### 4.3 数据量要求

czsc 的 `init_n=500` 意味着前 500 根 30 分钟 bar 不产出信号（约 63 个交易日）。
**要跑出结果至少需要 150 个交易日以上的 30 分钟数据。**

另注意 `core/chan.py` 记录的 czsc 约束：`bars_raw` 会从头截断，
所以 `result.trading_days` 可能少于输入的自然交易日数。

### 4.4 诊断字段

`ScanResult` 带三级信号的原始跃迁点，用于排查"为什么没触发"：

```python
result.buy1_days        # 日线一买生效日列表
result.buy2_days        # 日线二买生效日列表
result.m30_buy2_bars    # 30 分钟二买跃迁 bar 列表
result.trading_days     # 参与计算的交易日数
```

### 4.5 测试

`tests/test_chan_strategy.py` 共 **43 条**，分两层：

- **纯逻辑层**（不依赖 czsc）：窗口边界（15/16、2/3）、状态跃迁、
  同一 bar 不被重复消耗、均线止损切换、成交延迟、字符串价格回归
- **集成层**（需 czsc）：合成数据跑通完整链路，断言成交晚于信号、
  窗口约束成立、收窄窗口不增加买点（单调性）

## 5. 频率实测

合成 30 分钟数据（随机游走，seed 7），约 458 个自然交易日：

| 指标 | 次数 |
| --- | --- |
| 日线一买跃迁 | 17 |
| 日线二买跃迁 | 13 |
| 30 分钟二买跃迁（bar 级） | 112 |
| **三者共振（实际买点）** | **1** |

czsc 保留 396 个交易日后，换算约 **0.6 次买点/年**。

### 解读

1. **三重 AND 是强约束**。日线一买 17 次、二买 13 次，但要求"一买后 15 个交易日内
   出现二买"把候选压到个位数，再叠加 30 分钟二买就只剩 1 个。
2. **可配对的一买→二买组合只有 10 组**，其自然日间隔为
   `[11, 16, 18, 37, 43, 50, 83, 91, 100, 105]` —— 后 7 组都远超窗口。
3. **合成数据 ≠ 真实行情**。随机游走产生的缠论结构比真实行情稀疏得多
   （真实行情有趋势、有中枢震荡，一买二买会密集得多）。
   这个数字只能说明**量级偏低**，不能作为收益预期。

### 已用真实数据验证（2026-09-17）

数据源：新浪前复权 30 分钟 K 线，1970 根 / 247 个交易日
（2025-09-11 → 2026-09-17）。czsc `init_n=500` → 实际参与信号计算
1470 根 / 184 个交易日。

20 只流动性标的的扫描结果（脚本见第 8 节的可视化工具，同一数据链路）：

| 结果 | 只数 |
| --- | --- |
| 出现三重共振买点 | 4 |
| 未出现 | 16 |

命中标的：

| 标的 | 买点数 | 结果 |
| --- | --- | --- |
| sh688981 中芯国际 | 2 | +13.35% / +3.63%（均 MA10 出场） |
| sh601899 紫金矿业 | 1 | +4.63% |
| sh600276 恒瑞医药 | 1 | -2.40% |
| sh600887 伊利股份 | 1 | -0.80% |

**卡点定位**：未命中的 16 只里，30 分钟二买出现 18~65 次、日线二买
1~14 次，条件都不缺；卡在**日线一买**（20 只中 8 只为 0 次）和
「一买后 15 个交易日内必须出二买」的时序约束上。

**结论：单只标的约 0.2 次/年，比合成数据估的还稀，必须池化选股**
（几百只里挑当天触发的那几只），否则实盘一年等不到几次信号。
第 6 节第 3 问（要不要池化）因此从"可选"升级为"必选"。

## 8. 可视化（`core/chan_viz.py`）

把中枢、分型、笔、各级买卖点和本策略的结果画到一张图上，用来**肉眼复核
信号标得对不对**。产出是单文件 HTML（ECharts 内联），离线可看，不涉及
实时刷新。

```bash
python visualize_chan.py sh688981 --name 中芯国际
# → outputs/chan_sh688981_30min.html
```

图层：K 线 / 中枢 / 笔 / 分型 / 一·二·三买卖点 / 日线一买·二买生效日 /
策略买卖点 / 日线 MA5·MA10 / 成交量（副图）/ czsc 预热区间底纹。

### 画这张图时踩到的三个坑（改代码前先读）

1. **`generate_czsc_signals(df=True)` 会丢掉前 `init_n` 根**，返回的帧
   只有后段。图必须按 `warmup = len(df) - len(信号帧)` 把 x 轴铺成全量
   K 线、信号按尾部对齐，否则预热区间会伪装成"有信号但没触发"。
2. **自定义系列必须显式写 `encode: {x: [0,1], y: [2,3]}`**。
   ECharts 默认把第 2 个维度当 y 轴值，而中枢/预热区间的第 2 维是
   **下标**（最大 ~1900），不声明会把 y 轴从 110~180 撑成 0~2000。
3. **`core/chan.bis()` 的 `start_idx/end_idx` 基准是 czsc 的 `bars_raw`**，
   实测比输入少 7 根，不能直接当全量下标用 —— 必须按 `sdt/edt` 对齐。
   （`core/chan.py` docstring 已警告过这一点，这里又踩了一次。）
