## 2. 策略定义（窗口为 2026-09-18 重标定后）

### 2.1 买点：三重条件，有时间窗

| 序 | 条件 | 时间窗 |
| --- | --- | --- |
| 1 | 日线出现**一买** | — |
| 2 | 出现**日线二买** | 一买之后 **40 个交易日**内 |
| 3 | 出现 **30 分钟二买** | 日线二买**前后各 10 个交易日**内（双向） |

三条**全部确认**的那一刻即为买点，成交再顺延 1 根 30 分钟 bar。

窗口按**交易日**计算（不是自然日），边界含端点：第 40 个交易日算在窗内，
第 41 个不算；第 3 级同理 ±10 含端点。

⚠️ 第 3 级是**双向**窗口，因为几何法的 30 分钟买点常早于日线二买
（次级别先转势，实测紫金矿业早 6 个交易日）。但**允许配对 ≠ 允许提前成交**：
成交时点取「所有条件都确认之后」，触发 bar 若早于日线二买，成交推迟到
日线二买所在交易日的首根 bar 之后 —— 否则就是在用还没发生的信息交易。

### 2.2 卖点：日线均线的移动止损

> "均线最好是智能选取一直沿着上涨没有跌破的 5 或 10 日均线，可以先定为日线 MA5"

实现的解读（**待老三确认**）：

- 买入后以 **MA5** 为止损线
- 收盘跌破 MA5、但 MA10 仍完好 → **改用 MA10** 继续持有
- MA5、MA10 **双双被跌破** → 卖出

即"选出那条至今没被跌破的均线"，而不是"破 MA5 立刻清仓"。

### 2.3 成交时点：等确认，不抢跑

老三明确"不需要当时就知道，可以有半天到一天的延迟"。落地为：

| 动作 | 确认时点 | 成交时点 |
| --- | --- | --- |
| 买入 | 三级条件**全部确认** | 再顺延 **1 根** 30 分钟 bar，取该 bar 收盘价 |
| 卖出 | 日线收盘跌破均线 | **次一交易日**收盘价 |

参数：`entry_delay_bars=1`、`exit_delay_days=1`。
这样回测与实盘看到的是同一时点的信息。

⚠️ 两个来源的「确认时点」不同：

- **日线几何点**（一买/二买）落在笔的终点 = 某交易日 T 的收盘价上，
  但「它成立」要等 T 收盘才知道 → **生效日取 T 的次一交易日**。
  直接拿 T 当生效日就是 1 个交易日的未来函数。
- **30 分钟几何点**收盘即确定，不涉及未走完的更大周期 bar，直接用该 bar 时刻。

⚠️ **但这只消除了「价格要等收盘」这一层，还有第二层没处理（2026-09-20 补）**：
笔终点要等**后续反向笔成型**才会被锁定 —— T 当天 czsc 给出的 `bi_list[-1]` 是
**正在延伸的暂定笔**，终点随时会被改写。实测（`scripts/diag_geom_lag.py`，50 只
标的池、2020-07~2026-09 日线）：

| 口径 | 一买/二买滞后 |
| --- | --- |
| 切片重算 + 锁定条件（实测，抽样 18 点） | **+4 ~ +16 个交易日**（中位 ≈ 6.5） |
| 下一笔终点（保守上界，一买 408 点） | 中位 **9 个交易日**、P90 = 23 |
| **`offset=1` 的覆盖率** | **0%** |

⇒ 本节的回测成绩（73.9% / +3.90%）只能当**乐观上界**读，不是实盘可复现的水平。
同源的还有两处：一买的按中枢收敛是**全量事后选择**（回测与实盘的成交集合本身
不同），以及 `match_buy_points` 取「离 d2 最近」的触发点**用了窗口右半的信息**。
详见 `docs/KNOWN_ISSUES.md` KI-009 与 `outputs/geom_lag.md`。

## 3. 实测结论（两条，都有数据支撑）

### 3.1 信号是「持续状态」，不是「点事件」

czsc 的信号列**不是 0/1**，而是持续状态字符串：

| 列名 | 取值 |
| --- | --- |
| `日线_D1B_BUY1` | `一买_19笔_任意_0` / `其他_任意_任意_0` |
| `日线_D1#SMA#21_BS2辅助V230320` | `二买_任意_任意_0` / `二卖_任意_任意_0` / `其他_任意_任意_0` |
| `30分钟_D1#SMA#21_BS2辅助V230320` | 同上 |

实测日线二买状态连续覆盖 **352 根 30 分钟 bar（约 44 个交易日）**。

→ 所以"出现二买"必须定义为**状态跃迁**（首次进入该状态的那一根）。
若按"值里含二买"判定，15 日窗口形同虚设（状态一开就是 44 天）。

### 3.2 日线信号在日内会翻转 → 取当日首根 bar 的值

实测 **418 个交易日中有 45 天**，日线二买在**同一交易日内发生翻转**
（早盘读到"其他"、尾盘变"二买"，或反之）：

```
2023-05-26: 首根=其他  末根=二买   日内取值数=2
2023-05-24: 首根=二买  末根=其他   日内取值数=2
2024-03-14: 首根=其他  末根=二买   日内取值数=2
```

原因是当天的日线 bar 尚未走完，czsc 会拿当天已发生的部分 30 分钟合成日线参与计算。

**本模块的处理**：日线信号按交易日取**首根 bar 的值**，等价于「上一交易日收盘确认」
的状态。好处是实盘开盘就能读到、回测与实盘一致；代价是日线信号滞后 1 个交易日。

> **对窗口的影响：无。**
> 一买、二买都整体后移 1 个交易日，位置差不变，`gap` 值与用真实发生日计算完全相同。

### 3.3 关于"未来函数"的结论修正

本文件 v1 曾判断"批量接口把日线信号回填到了当天第一根 30 分钟 bar 上，构成未来函数"。
**该判断不准确，此处更正：**

- 实测日线信号的日内变更发生在第 **1~7** 根 bar，**从不在第 0 根**（首根）
  —— 说明不是"回填到第一根"
- 切片重算（只喂到时刻 t）与全量回看的结果 **5/5 完全一致**
  —— 说明批量路径与因果路径等价，没有使用 t 之后的数据

**真正的问题是信号日内不稳定，不是未来函数。** 而"取当日首根 bar 值"这一处理，
同时消除了两者风险。

## 4. 实现

### 4.1 模块接口

```python
from core.chan_strategy import scan

result = scan(klines_30min, code="600000")   # klines: list[KLineData]
result.source                                # 'geometry'（默认）/ 'signal'
result.summary()
# {'买点数': 1, '已平仓': 1, '未平仓': 0, '胜率%': 0.0,
#  '平均收益%': -2.81, '平均持有交易日': 2.0,
#  '最大同时持仓': 1, '重叠笔数': 0, '重叠对数': 0, ...}

# 换回旧实现做对比（保留用于回归）
sig = scan(klines_30min, code="600000", source="signal", max_gap_1to2=15,
           max_gap_2tom=2)

for t in result.trades:
    t.buy.dt, t.buy.price, t.buy.signal_dt     # 成交时刻 / 价 / 触发时刻
    t.buy.d1, t.buy.d2, t.buy.gap_1to2, t.buy.gap_2tom   # gap_2tom 有符号
    t.sell.dt, t.sell.price, t.sell.ma, t.sell.hold_days, t.sell.confirm_dt
```

两个底层函数（一般不必直接用）：

- `points_from_chan(klines_30m, df_30m)` —— 建 czsc 对象 + 产三级点事件
- `points_from_structures(bis_m30, centers_m30, bis_daily, centers_daily, ...)`
  —— 只用**已算好**的结构产点事件（可视化层用这个，省掉一次重复建对象）

### 4.2 关键参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `source` | `"geometry"` | 取点来源。`"signal"` = 旧 `cxt_*` 实现 |
| `max_gap_1to2` | **40** | 一买 → 二买 的最大间隔（交易日）。**旧值 15** |
| `max_gap_2tom` | **10** | 30 分钟二买相对日线二买的**双向**窗口（±10）。**旧值 2（单向）** |
| `ma_short` / `ma_long` | 5 / 10 | 卖出用的短/长均线 |
| `entry_delay_bars` | 1 | 买入成交相对**全部条件确认**的延迟（根） |
| `exit_delay_days` | 1 | 卖出成交相对确认日的延迟（交易日） |
| `ma_type` / `timeperiod` | SMA / 21 | **仅 signal 源**用：czsc `cxt_second_bs` 的信号参数 |

### 4.3 数据量要求（两个门槛，别混为一谈）

**代码硬门槛**（两个源的门槛不同）：

- `source="signal"`：30 分钟 bar 数 > `init_n + 60`（默认 560 根 ≈ 70 个交易日）。
  560 根里 czsc 前 500 根不产信号，实际只有 60 根可用（≈7.5 个交易日）。
- `source="geometry"`：`GEO_MIN_BARS = 480` 根（≈60 个交易日）。几何法**没有**
  `init_n` 预热，但日线要能形成中枢（≥3 笔）才谈得上一买，门槛反而更高。

**有效下限**：两个源都远高于代码门槛 —— 20 只流动性标的 / 246 个交易日里，
几何源 12 只零买点（见第 5 节）。

另注意 `core/chan.py` 记录的 czsc 约束：`bars_raw` 会从头截断，
所以 `result.trading_days` 可能少于输入的自然交易日数。

### 4.4 诊断字段

`ScanResult` 带三级点事件的原始列表，用于排查"为什么没触发"：

```python
result.source           # 'geometry' / 'signal'
result.buy1_days        # 日线一买生效日列表
result.buy2_days        # 日线二买生效日列表
result.m30_buy2_bars    # 30 分钟二买（几何源=点所在 bar；signal 源=状态跃迁 bar）
result.trading_days     # 参与计算的交易日数
```

2. **几何源与 signal 源的买点几乎不重叠**。不是"改良"，是两批不同的信号。

3. **signal 源在新窗口下笔数暴涨但质量下降**（6 → 32 笔，+2.87% → +0.61%）。

   大量噪声。反过来也印证：原 15/2 是为密集状态量身定的，不能直接搬到稀疏点上。

### 5.2 换源前后为什么 0 笔（窗口重标定的依据）

几何源在**原口径（15 / 2）下 8 只标的全部 0 笔**。逐级查下来：

| 卡点 | 只数 | 说明 |
| --- | --- | --- |
| 日线一买为 0 | 4 | 该股这段行情里日线级别就没有下跌趋势终结 |
| 一买→二买超 40 日 | 2 | 恒瑞 54 日、兴业银行 44 日 |
| 30 分钟买点超 ±10 日 | 8 | **主要瓶颈** |
| 成交 | 8 | — |

**关键观察：超窗的那 8 只，偏移量是 +15 / −11 / −12 / −21 / −26 / −28 / −31 / −35 个交易日
—— 半数差 3~5 周，不是"差一点"。** 这说明这些日线二买**根本没有对应的次级别买点**，
两级的时间尺度本来就不耦合。所以：

- 把 ±10 放宽到 ±20 能多捞 3~4 只，但那是"任意找个 30 分钟买点"，
  第三级的择时意义就没了 —— 会退化成 `cxt_*` 那种"靠密度不靠精度"。
- **窗口要真标定，得先把标的池扩到 100~300 只**（见第 7 节第 1 条）。
  现在的 40 / ±10 是老三拍的（40 = 24 只实测间隔中位数 33 + 余量），
  不是寻优结果。

### 6.1 已定案（别再翻出来问）

**持仓口径：每个买点独立成一笔交易，允许重叠持仓**（老三 2026-09-18 定）。

前一笔未平仓时新买点照开。定案理由是当前目的为**验证买卖点是否成立**，
不是做组合回测——把"信号质量"与"资金约束"解耦，避免"没资金了所以没买"
这类组合层面的事盖住信号本身的问题。

由此产生的口径，读数字前必须知道：

- `summary()` 的胜率 / 平均收益 / 平均持有是**按笔统计**，**不是资金曲线**。
  同一时刻若有 N 笔持仓，收益不可直接相加成组合收益。
- `summary()` 同时返回 `最大同时持仓` / `重叠笔数` / `重叠对数`
  （`position_overlap_stats()`），用来自查重叠程度。重叠占比高时，
  按笔统计的结论要打折看。
- 未平仓那笔（`sell is None`）视为一直持有到数据末尾，与之后所有买点重叠。
- 统计时**同一时刻先平后开**：卖在买当天算换仓，不算两笔同时在手。

**实测（几何源 / 20 只 / 246 个交易日）**：8 笔买点、重叠 0 笔、
最大同时持仓 1。当前样本里重叠仍未发生，按笔统计与组合口径暂时等价；
标的池扩大后直接从 `summary()` 读重叠笔数即可。

**什么时候要改**：接组合回测 / 资金曲线 / 仓位管理时，二选一——
"持仓中忽略新买点"（单持仓）或按仓位分配。改点在 `scan_from_frame` 组装
`trades` 的那段循环；`position_overlap_stats` 可直接作回归判据
（改完 `最大同时持仓` 必须为 1）。

### 画这张图时踩到的三个坑（改代码前先读）

1. **`generate_czsc_signals(df=True)` 会丢掉前 `init_n` 根**，返回的帧
   只有后段。图必须按 `warmup = len(df) - len(信号帧)` 把 x 轴铺成全量
   K 线、信号按尾部对齐，否则预热区间会伪装成"有信号但没触发"。
2. **自定义系列必须显式写 `encode: {x: [0,1], y: [2,3]}`**。
   ECharts 默认把第 2 个维度当 y 轴值，而中枢/预热区间的第 2 维是
   **下标**（最大 ~1900），不声明会把 y 轴从 110~180 撑成 0~2000。
3. **`core/chan.bis()` 的 `start_idx/end_idx` 基准是 czsc 的 `bars_raw`**，
   实测比输入少 7 根，不能直接当全量下标用 —— 必须按 `sdt/edt` 对齐。
   （`core/chan.py` docstring 已警告过这一点，这里又踩了一次。）

### 数据源

  （约 246 个交易日）。东方财富的分钟接口只给最近约 250 根，**不够
  czsc 的 500 根预热**；通达信（mootdx）端口在部分网络环境下不通。
